# 东澳岛页面改造 · 快速上手（现状 + 新资料 + 改动研判）

> 生成时间：2026-10-31。本文是对现有代码与新资料的**静态研判**，未改任何代码、未真机验证。
> 详细材料：[`docx-summary.md`](docx-summary.md)（6 份 docx 解读）、[`data-summary.md`](data-summary.md)（5 份 xlsx + 56 个菜单 PDF 审阅）。

## 0. 一页结论

1. **现有东澳岛页只做了一件事**：定位 → 按 GPS 距离取最近景点 → AI 生成 1 条 14–28 字任务（附提示、安全语）→ 带 1 条 mission 跳记录页。数据只有"景点名 + 坐标"。
2. **新资料不是成稿**：6 份 docx 是"内容生产方法论 + 4 个客群的攻略骨架"（3 份攻略书的项目列表整段空白），5 份 xlsx 是按 12 字段采的一版初稿，**0 个经纬度**、跨表重复、客群标签 8 种写法，菜单 PDF 全是图片。
3. 所以"稍加修改"的现实解是：**不碰推荐/生成主链路**，先把数据补成可入库的形态（坐标 + 扩字段），再让卡片长出"客群 / 线路站序 / 时长 / 预算 / 预订"这些字段。票券、核销、收藏、订单在 6 份文档里 **0 次出现**，默认不做。

## 2. 改之前要知道的 6 个现状问题

1. **首屏不定位**：`onLoad` 只填 `allSpotNames`，用户看到空卡片，必须手动点"定位"——与设计文档"懒人设计"相反。
2. **开发能力对线上可见**：`dev-toggle` 常驻页面，里面有"初始化 spots / 建 geo 索引 / 测试天气潮汐 / 测试推荐 / 测试生成 / 模型输入输出"；"模拟位置" picker 也在主 UI 上。
3. **错误文案暴露部署信息**：`errorMsg` 默认是"请先部署云函数并初始化spots集合"。
4. **云存储 fileID 硬编码云环境 ID**（`dongaoGenerate/index.js:286-289` 写死 `cloud1-2gdui7md5af99e5c`），换环境必然读不到。
5. **历史卡片名不副实**：设计文档说左滑读 `dongaoCards` 集合，实际客户端**完全不读该集合**（`miniprogram/` 内 0 处引用），`historyCards` 只在内存里，冷启动即丢失。
6. **岛外必空**：`geoNear` 半径 20km，用户不在岛附近时返回空列表 → 只弹"暂无景点数据"，没有"先上岛"引导。

- **应填尽填**：岛上现存项目一个不能漏；

- 三级标签 = **游客在这个项目能做什么**；
- 核心地点 = **观光车几号线第几站**（岛上接驳车 1/2/3 号线是刚性结构）。

4 类客群：Z世代/情侣、亲子/自然教育、银发/休闲、资深玩家/硬核探索。

### 3.3 菜单 PDF

16 家店 56 个 PDF，**全是图片型**（0 文字层）：团购页 ≈32、菜单照片 ≈13、纯文字长截图 ≈10、无效 1。OCR 实测：长截图可全自动（抽样 16/16 菜品+价格正确）；团购页只能抽套餐总价；翻拍照片需人工校对。38 家餐厅里 22 家没有菜单。

## 4. 差距：现状 vs 文档要求

| 维度 | 现状 | 文档要求 | 阻塞程度 |

## 5. 三档改动，推荐先做 A

### A. 数据入库 + 卡片涨字段（1–2 天，低风险）
- 新脚本把 5 份 xlsx 合成一张清洗表：**去重（约 110 个实体）+ 标签归一 + 保留 `sourceFile` 溯源**；
- 高德 POI/地理编码补坐标，人工抽检 10%，**只把有坐标的写进 `spots`**；
- `spots` 扩内容字段（不动 `location`/`geoNear` 逻辑）；
- `dongaoRecommend` 返回扩字段 → 卡片多一行 meta（时长 / 预算 / 预订 / 线路站）；
- 顺手修 §2 的 1、2、3、6（自动定位、隐藏开发工具、人话错误、岛外引导）。

改：`cloudfunctions/dongaoRecommend/index.js`、`cloudfunctions/dongaoGenerate/index.js`（prompt 注入字段，可选）、`pages/dongao/*`；新增 `scripts/` 导入脚本。

### B. 客群入口 + 任务组（+3–5 天）
- 顶部 4 个客群 chip，默认按当前点位的主匹配客群；
- `dongaoGenerate` 输出从 `{mission,tips,safetyNote}` 扩成 `{audience, missions[3], tips, safetyNote, booking}`，每条 mission 带三级玩法标签；
- `themeSnapshot.missions` 从 1 条变 N 条，**record / history / walk-detail 不用改**；
- `dongaoCards` 增记 `audience` / `missions`。

### C. 路线 + 多日行程（+1–2 周，需要产品先行）
- 新增 `routes`（1/2/3 号线 + 站序）与 `itineraries`（客群 × 天数 × 时段 × 点位）；
- 页面从"单卡"变"按天日程"；record 页 mission 列表需要 `dayIndex` 分组（现在没有）。
- 前置条件：文档里情侣/资深玩家两个客群的"几天几夜"**还没定**，数据也还没成形。

## 6. 建议开工顺序（每步可独立验证）

1. **清洗**：5 份 xlsx → 一张 json/csv（去重、标签归一、保留来源行号），产出实体清单；
2. **geocode**：补坐标 + 抽检，输出 `coords`/`location` 可写入的导入包；
3. **入库**：先"关联"再"新增"——能在现有 52 个 spot 里按名字对上的（婚礼堂、蜜月阁、滨海栈道、月牙环、风车山、求子泉、铳城、山海经书屋、海洋生物科普馆、海关遗址等约 10 条）补字段；餐饮/住宿/购物属于纯新增；
4. **接口**：`dongaoRecommend` 返回扩字段（保持 geoNear，可把 limit 从 20 提到 50）；
5. **页面**：卡片加字段行 + 修 §2 的体验问题；`dongaoGenerate` prompt 注入"客群 + 时长 + 最佳时段 + 预算 + 安全"。

无坐标的 37 条活动（含 11 条酒店住客权益）**不要硬塞 spots**，后续单独建 `activities` 用 `spotName` 关联。
